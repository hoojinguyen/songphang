# Sòng Phẳng — iOS Interface Stage (5U) Implementation Plan

> **For the implementation agent:** read the root `AGENTS.md`, then `apps/ios/AGENTS.md`, then the two specs below, then this file. Work through the tasks in order without stopping between them (AGENTS.md section 12). The project does not write automated tests.

**Goal:** Every phase 1 screen of the iPhone application, complete and navigable in the Simulator on scripted data, built while the API and the web are still changing and without touching their files.

**Architecture:** The modules of the architecture design that do not need a server: `Domain`, `DesignSystem`, `PreviewSupport`, the four feature modules and `AppShell`. Screens receive repository protocols; in this stage the only implementations are the scripted fakes of `PreviewSupport`. `GeneratedAPI` and `Repositories` are not created; they arrive in the integration stage and replace the fakes in one place.

**Tech Stack:** Swift 6, SwiftUI, minimum iOS 26, one Swift package. No dependency of any kind in this stage.

**Specs:** `docs/superpowers/specs/2026-11-16-ios-codebase-architecture-design.md` ("AD"), which decides structure, and `docs/superpowers/specs/2026-11-15-phase-5-ios-design.md` ("P5"), sections 5.2 and 5.3, which decide behavior.

**Branch:** `ios-ui`, in its own git worktree at `../songphang-ios-ui`. **Run files:** `docs/superpowers/runs/ios-ui/` (`progress.md`, `decisions.md`, `manual-checks.md`, `screens/`). **Last task:** U.8.

## Global Constraints

- **Write only under `apps/ios/` and `docs/superpowers/runs/ios-ui/`.** Everything else in the repository is read-only for this run: no edit, no formatting, no "small fix". Another agent is changing `apps/api`, `apps/web` and `packages/` on another branch at the same time. A defect seen there goes under "Out of scope" in `progress.md`.
- **No server.** Nothing in this stage opens a network connection. Do not start `pnpm dev`; do not add `URLSession` code.
- **No money logic, not even in a fake.** `Money` offers addition, subtraction and comparison only. A fake never divides, multiplies, rounds or allocates. Every share, balance and suggested transfer a fake returns is a literal written in a scenario file and transcribed from a captured response of the real API (`docs/superpowers/runs/ios-ui/fixtures/`).
- **Dependency rule:** each target in `Package.swift` depends on exactly the modules AD section 5 lists. Adding a dependency to make something compile is never a "decide and record" matter; the code moves to the module where it belongs.
- **Strings:** P5 section 3 and the phase 5 plan's strings constraint, unchanged: `Localizable.xcstrings` holds exactly the strings of `apps/web/src/messages/vi.ts` plus the iOS-only ones of P5 5.3.
- **Screens:** when a web screen exists, the iOS screen has the same content, order and strings; platform conventions replace only navigation chrome and controls. Sizes not given are taken from the web component.
- **Performance:** AD section 8.2 applies to every screen.
- **Automated gate** (replaces `pnpm check` for this run), run from the worktree root:
  - `xcodebuild -project apps/ios/SongPhang.xcodeproj -scheme SongPhang -destination 'generic/platform=iOS Simulator' SWIFT_TREAT_WARNINGS_AS_ERRORS=YES build` → `BUILD SUCCEEDED`
  - `xcrun swift-format lint --strict --recursive apps/ios` → no output
  - Never silence a warning with an attribute, a force unwrap or a force cast.
- **Commits:** one per task on `ios-ui`, `type(ios): short description`. No push.
- **Screenshots:** `xcrun simctl io booted screenshot`, saved under `docs/superpowers/runs/ios-ui/screens/`, named `<screen>-<state>.png`.
- If Xcode or the iOS 26-or-newer Simulator runtime is missing, record "Not built: no Xcode" and stop. Do not install anything.

## Not in this stage

`GeneratedAPI`, `Repositories` (transport, Keychain, snapshots, event stream), real sign-in sheets (`ASWebAuthenticationSession`, Sign in with Apple), push, universal links, the upgrade screen, release configuration, and anything of phases 2–4. The integration stage builds them after stage 5A of the phase 5 plan.

## Review Focus

1. **A fake computes money.** A share or balance that is not a literal transcribed from a captured response. → U.3.
2. **A screen reaches around its protocol**, or a feature imports another feature. → U.1, U.8.
3. **A screen differs from the web's** content, order or strings. → U.4–U.7.
4. **A screen lacks one of its states**, or a failed refresh wipes shown content. → every screen task.
5. **Scripted data reaches a release build.** → U.3, U.8.

## Per-task procedure

That of the phase 1 overview, with the gate above in place of `pnpm check`, the Simulator in place of the browser, and "Rules for every task" of the phase 5 application plan (`2026-11-15-phase-5/5b-5e-app.md`) for screens, resources, reads and navigation. In step 2 of every screen task the gate includes: each `#Preview` compiles.

### Task U.3: Domain, repository protocols, scripted fakes

**Sources (read-only):** `packages/contract/src/*.ts` for every type and field; `apps/web/src/lib/*.ts` for which calls a screen makes; `docs/superpowers/runs/ios-ui/fixtures/` for real response shapes and every amount.

**Files:** `Domain/Models/` (`User`, `ServerFeatures`, `ExpenseGroup`, `Member`, `Role`, `Invite`, `LedgerTransaction`, `TransactionDraft`, `SharePreview`, `Balance`, `SuggestedTransfer`, `ActivityItem`, `QuickEntryReading`, `GroupEvent`, `Page`); `Domain/Repositories/` (`AuthRepository`, `GroupsRepository`, `MembersRepository`, `InvitesRepository`, `TransactionsRepository`, `BalancesRepository`, `ActivityRepository`, `QuickEntryRepository`, `GroupEventsRepository`); `PreviewSupport/Scenarios/`, `PreviewSupport/Fakes/`, `PreviewSupport/Samples/`

**Interfaces — produces:**
- Domain types follow the contract's field names and optionality as of the web baseline. Each server enumeration is a Swift enum with a fallback case. Identifiers are distinct types per entity. Where the contract is unclear, record the choice in `decisions.md` under **"Domain guesses"**; that list is the integration stage's checklist.
- Protocols as AD 7.1 and the "Rules for every task": every read has `lastKnown…()` and a fetching function; every function but `lastKnown…` and `events` is `async throws(AppError)`; `struct Page<Item: Sendable>: Sendable { let items: [Item]; let nextCursor: String? }`. `AuthRepository` has `currentUser()`, `signIn(email:password:)`, `signInWithGoogle()`, `signInWithApple()`, `register`, `requestPasswordReset`, `resendVerification`, `serverFeatures()`, `signOut()`; the integration stage splits the Google and Apple functions into their real steps.
- `actor FakeWorld`: the state behind every fake. `struct FakeBehavior: Sendable { var latency: Duration; var failure: AppError?; var hasSnapshot: Bool; var role: Role }`, changeable at run time. Every fake repository is a thin type over `FakeWorld`. With `failure` set, every fetching and writing function throws it; `lastKnown…` returns the current value when `hasSnapshot` is true and `nil` otherwise.
- Scenarios, each one a file of literals:
  - `empty`: a signed-in user with no group.
  - `trip`: the four seeded people (Minh, Lan, Hùng, Thu) and one group, in five steps: no transaction, then after each of T1–T4. Each step's transactions, shares, balances and suggested transfers are transcribed from the fixture captured at that step. The scenario can start at step 0 (for entering) or step 4 (for reading).
  - `large`: one group with 500 transactions generated by repeating literal rows with distinct identifiers and dates; balances are one literal set.
- Writes: creating, editing or deleting a group, member or invite changes `FakeWorld` directly. A transaction write is accepted only when the draft equals one of T1–T4 (the world advances to that step's literal balances) or a draft produced by a scripted sentence; `preview` likewise. Any other draft throws `.api(code: "FAKE_UNSCRIPTED", status: 422)`. `parse` returns the captured reading for the ten fixture sentences, and the fixture's `unparsed` shape for any other text.
- `GroupEventsRepository` fake: yields the event the debug panel sends.
- All of `PreviewSupport` is inside `#if DEBUG`.

- [ ] **Step 1: Write it**
- [ ] **Step 2: Gate.** Search `PreviewSupport` for `/`, `*`, `%`, `.rounded`, `quotientAndRemainder` applied to an amount → none (Review Focus 1); paste the search and its output. In `progress.md`, a table: scenario file → the fixture files it was transcribed from. Compare three amounts per step against the fixtures by hand and paste them.
- [ ] **Step 3: Commit** — `feat(ios): add domain types, repository protocols, and scripted fakes`

### Task U.4: Shell, debug panel, sign-in (S1 and the account entry screens)

**Web sources:** `apps/web/src/app/login`, `register`, `verify-email`, `forgot-password`, `reset-password`; phase 1 spec section 9.1–9.4.

**Interfaces — produces:**
- `struct AppDependencies` with one field per repository protocol and `static func scripted(world: FakeWorld) -> AppDependencies` inside `#if DEBUG`. There is no other constructor in this stage: a Release build fails to compile at the composition root with a `#error("Live repositories arrive in the integration stage")`, so scripted data cannot ship (Review Focus 5).
- `@Observable final class SessionModel` with `enum State { case loading, signedOut, signedIn(User) }`; any `.unauthorized` moves it to `.signedOut`.

- `DebugPanel` (debug builds, opened from a toolbar item on the group list and by shaking): choose the scenario; set latency (0, 300 ms, 2 s); toggle offline, a failure of each `AppError` case, "has snapshot"; choose the role; send a `changed`, `removed` or `reconnected` event; sign out.
- S1: `Đăng nhập với Apple` above `Tiếp tục với Google` (each shown when `serverFeatures()` says so; the fake signs in at once), email and password, links to register and forgot password. The system sign-in sheets are not built in this stage.
