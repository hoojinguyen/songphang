### Task 5C.1: Native Google exchange

**Files:** `apps/api/src/routes/{google,mobile-auth}.ts`, `apps/api/src/auth/google.ts`, `apps/api/src/services/{google-sign-in,mobile-auth}.ts`, `packages/db/src/schema-accounts.ts` and next migration, `packages/contract/src/auth.ts`, OpenAPI snapshot, `Domain/Repositories/AuthRepository.swift`, `Repositories/Auth/`, `AuthFeature/SignIn/`, `apps/ios/App/Info.plist`.

**Interfaces:** `GET /auth/google?client=ios&code_challenge=…` adds a native branch to the existing browser flow. S256 challenge is a 43-character unpadded base64url SHA-256 value. Keep this challenge and the native client identifier bound to the existing OAuth state. Web's existing cookie-session and sanitized redirect behavior remain. Native callback issues one short code, hash-stored under purpose `mobile_exchange` with the native challenge and client context, TTL 60 seconds. It uses the fixed `songphang://auth` callback and creates no session cookie. `POST /auth/exchange` takes `{ code, codeVerifier, client, deviceName }`, accepts the RFC 7636 verifier character set and length 43–128, rate-limits and consumes the code atomically, and returns `{ token, user }` with no-store on success. Reuse 5A session creation. The failing exchange response uses `TOKEN_INVALID`.

- [ ] Implement server and native flow. Show Google from `/auth/providers`, use `ASWebAuthenticationSession`, retain a random verifier only for the initiating flow, and accept only expected callback scheme/host and query shape. Keep the token inside Repositories. Register the callback scheme for sign-in. Rebuild the snapshot and iOS client.
- [ ] Issue a code through the local service in a disposable exercise. Verify one success, concurrent attempts produce one session, expiry, wrong verifier, wrong client context and replay are refused. Verify the router rejects an unrelated callback, a native request requires a challenge, and web retains its own callback contract. Provider completion is unverified pending owner Google credentials.
- [ ] Run the task gate and commit `feat(auth): add PKCE-bound native Google sign-in`.

### Task 5C.2: Apple sign-in and account deletion revocation

**Files:** new `apps/api/src/auth/apple/` for key set, verifier and token adapter, `apps/api/src/services/apple-sign-in.ts`, account deletion service, `apps/api/src/routes/{mobile-auth,features}.ts`, Zod API config, `packages/db/src/schema-accounts.ts` and next migration, `packages/contract/src/auth.ts`, `.env.example`, README, OpenAPI, `Domain/Repositories/AuthRepository.swift`, `Repositories/Auth/`, `AuthFeature/SignIn/`, `apps/ios/App/SongPhang.entitlements`.

**Interfaces:** `POST /auth/apple` takes `{ identityToken, rawNonce, authorizationCode, name?, client, deviceName }` and returns 200 `{ token, user }`; use `features.appleSignIn`. Validate signature with the matched Apple key and fixed expected algorithm, issue time, issuer, bundle audience, expiry and the chosen SHA-256 nonce encoding shared with iOS. Cache keys for 24 hours with bounded refresh on unknown key ID. Use the verified Apple subject and the existing verified-account linking policy, including relay email and repeat login with missing optional name. Keep the SHA-256 nonce convention identical across client and API.

**Provider boundary:** `APPLE_PROVIDER=apple` requires `APPLE_BUNDLE_ID`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` and 32-byte base64 `DATA_ENCRYPTION_KEY`. Real exchange stores the refresh token encrypted using AES-256-GCM as `v1:` + base64(12-byte IV, ciphertext, 16-byte tag). Revoke before completing account deletion, with a recoverable failure if revocation cannot complete. A failed production exchange must not leave a new identity without revocation material. `APPLE_PROVIDER=fake` validates a locally signed token against `APPLE_FAKE_JWKS_FILE`, simulates revocation and skips real exchange. Missing provider means the flag is false and the route returns 404. Production refuses the fake provider.

- [ ] Read Apple's [token validation](https://developer.apple.com/documentation/SigninwithAppleRESTAPI/Generate-and-validate-tokens) and [token revocation](https://developer.apple.com/documentation/SigninwithAppleRESTAPI/Revoke-tokens) guidance before implementation. Add native `AuthenticationServices` with the spec copy and button ordering. Keep the app usable with the provider disabled and handle system cancellation through the existing sign-in flow.
- [ ] Use locally signed fixtures to exercise new identity, repeat login, verified and unverified matching email, invalid issuer, audience, nonce, expiry, signature and unknown signing key. Exercise encrypted secret round-trip and tamper refusal locally, the fake revocation path, disabled flag/404 and production refusal. Real account authorization and revocation remain external.
- [ ] Regenerate, run the task gate and commit `feat(auth): add Apple sign-in and revocation lifecycle`.

**Interfaces:** `POST /me/devices` accepts `{ platform, token, environment }` only for a native session and upserts by token to the current user/session. Return `{ id }`; the token is never returned or logged. Cap at 10 current devices per user. Device users and sessions have cascade deletion. `DELETE /me/devices/{id}` is caller-owned. `PUT /me/push-settings` accepts `{ hideContent }`; expose the setting additively in `GET /me`. `features.push` reflects configured push availability; disabled routes return 404. API and worker use the same validated `PUSH_PROVIDER` selection and production excludes console.

- [ ] Register twice, rebind one token to a new native session, exercise cookie registration refusal, foreign device denial, device cap, logout, remote session revoke and deletion cascades. Inspect serialized responses and logging for device-token exposure. Regenerate, run the task gate and commit `feat(api): add native push registration and preferences`.

### Task 5C.4: Push sender and delivery guard

**Files:** `apps/api/src/services/notify.ts`, `packages/contract/src/jobs.ts`, worker job registration and config, new `apps/worker/src/push/`, new `apps/worker/src/jobs/send-push.ts`, current notification text helpers, `.env.example`, README.

**Interfaces:** `PushSender.send(device, message): Promise<"sent" | "gone" | "failed">`; `message` contains title, body, groupId and allowlisted target. Queue `send-push { notificationId }` via the existing transactional notification writer for immediate kinds plus expense/comment additions. Use the notification ID to deduplicate queue entries. Before each send, look up unread state, current membership, mute, content preference, and the device's active session. Use the group title and reuse `packages/core/src/notification-text.ts` for current inbox wording, or the spec's hidden-content body. The console adapter logs sanitized local observations. The APNs adapter uses HTTP/2, a cached provider token, the configured environment/topic and bounded request time. Prune only a definitively unregistered token; ensure a response for an old registration cannot delete a concurrently rebound device.

- [ ] Implement against Apple's [APNs token connection](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns) and [APNs request guidance](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns). - [ ] With two devices registered, observe one sanitized delivery per device, the exact hidden body when selected, no push when muted/read/removed/revoked before dispatch, and continued delivery on the remaining active device after sign-out from the other. Verify worker production refuses console mode and disabled configuration queues no send job. Run the task gate and commit `feat(worker): send privacy-checked push notifications`.
