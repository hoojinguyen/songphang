# Sòng Phẳng — Phase 3 Implementation Plan — Overview

> **For the implementation agent:** read `AGENTS.md`, the spec, `../2026-11-15-common.md`, then this file. Work through the stage files in order without stopping between tasks.

**Goal:** A user photographs a bill, assigns items to people and saves; photos are kept with transactions; the typing box understands sentences the rule reader refuses.

**Architecture:** A new process `apps/worker` runs jobs from a pg-boss queue in the same Postgres and tells the API about changes through `LISTEN/NOTIFY`. Files sit behind a `FileStore` interface on local disk. The AI is two interfaces (`ReceiptReader`, `SentenceAi`) with a real adapter never called by the agent and a fixture adapter. Whatever the AI returns is validated by a Zod schema and every share is computed by `packages/core`.

**Tech Stack:** unchanged, plus `pg-boss` (latest stable; record version, license and unpacked size in `decisions.md` when installing).

**Spec:** `docs/superpowers/specs/2026-11-15-phase-3-smart-entry-design.md`

## Constraints for this phase

- **The agent never calls the Anthropic API**, not even to "check the shape". The real adapter is written from the documentation at `https://platform.claude.com/docs/en/api/messages` and its pages on vision and tool use, read at the time of the task; record the date read and the request shape used in `decisions.md`.
- The API key is read from the environment in the adapter and nowhere else. It never appears in a log line, an error, an `ai_calls` row or a run file. A failed call logs the HTTP status and the provider's error type only.
- No prompt, image or model response is written to a log or stored outside `receipt_scans.result`, which holds only the validated reading.
- Text from an image or from the AI is rendered as plain text. It is never interpreted as a member id, a URL, a file path, HTML or an instruction.
- A storage key is generated by the server. No path on disk ever contains a client-supplied string.
- Every amount from a reading is an integer validated by Zod. A non-integer fails validation; nothing is rounded outside `core`.
- The worker depends on `db`, `core` and `contract` only. It does not import from `apps/api`.
- `pnpm dev` starts the worker with the API and the web app (a `package.json` change approved with the spec).

## Review Focus

1. **A stranger opens a photo.** Attachment content is served only through the group middleware; an id from another group is 404 even for that group's owner. → 3A.2.
2. **A file that is not an image is stored or served as one.** Type comes from the leading bytes; responses carry `nosniff`. → 3A.2.
3. **An AI number reaches the ledger unchecked.** Nothing is saved by a scan; saving is an ordinary create whose shares `core` computes. → 3B.3, 3C.2.
4. **Items that do not add up are saved.** `Σ items + net extra = amount` or the API refuses. → 3C.1, 3C.2.
5. **The AI bill runs away.** The per-user and monthly ceilings hold when requests arrive in parallel. → 3B.2.
